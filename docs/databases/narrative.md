For this enhancement, I have also used the Travlr Getaways web application used in the other enhancements. This artifact was created during my CS-465 Full-Stack development class. It is a MEAN stack web application designed for a fictional travel agency, and I have specifically focused on the single-page admin application portion of it. This single page allows admin users to manage existing trip packages or create new ones. 
	In this enhancement, I migrated the application’s database from a MongoDB no-sql database to a sqlite database. Sqlite was used here to simulate the use of a full sql database, since it is a friendlier format for turning in as an assignment submission. The first step in doing this was to create the database file and set up the schema to match the two tables in the mongo version. Then I needed to adjust the model and controller files for Users and Trips, the two primary data sets being used in the app. This change required defining custom classes in the model files rather than using the mongoose API objects and their native methods. New methods had to be designed to perform CRUD operations that are explicitly defined in SQL in the new files. While this change doesn’t visibly effect the app in its’ current state, moving to SQL improves the scalability by switching to a relational data model. The data sets used in this app are mostly static and don’t require the flexibility that would normally warrant a no-sql database, and in the future if functionality to link users and trips together is added, foreign keys and a relational data structure makes that process much smoother.
